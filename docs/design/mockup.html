SelfKaizen — Monochrome

基本は白黒（彩度 0%）。超過時のみ赤を1色だけ使います。 Light / Dark は OS の設定に自動追従します（下の切替は確認用のプレビュー）。

00 — 状態の伝え方（確定）

基本は白黒。リングの状態は形で3段階に分けます。 赤は「決めたルールを破った」という1つの意味だけに使い、 超過したときだけ適用します。 通常時は赤が1つも出ないため、赤が出たこと自体が情報になります。
状態リングの形色読み取れる意味
OK途切れた円弧（52%） 黒まだ余白がある
CLOSEほぼ閉じた円弧（92%） 黒埋まりかけている
OVER全周の点線 赤 円が壊れた＝超過
加えて文字が状態を明言します（18m left / 42m over）。 形・色・語の三重で伝えるため、どれか一つを見落としても状態は分かります。
赤くなる箇所発火条件
リングと 42m over の文字 1日の合計が上限を超えた
7日間チャートの超過した日 その日 上限を超えた
赤はこの2箇所のみ。 勤務時間帯のルールは設けない方針のため、 「いつ何を使ったか」はアプリ別ランキングと7日間チャートで示し、 判断は本人が行います。アプリが違反を判定して赤く染めることはしません。

04 — 判断と、正直な懸念

トレードオフ

状態が読めるまで僅かに遅くなる

色は前注意的に効きます（見る前に伝わる）。形は注意して読みます。 モノクロ化で状態把握は数十ミリ秒遅くなります。 代わりに得るのは上質さ・静けさ・長く使えること。 毎日開く道具では妥当な交換と判断しました。

代償設計

形・太さ・語で差をつける

途切れた弧 → 閉じた弧 → 全周の点線。3段階を形だけで区別します。 さらに left / over の語が明言するので、 形を見落としても文章で分かる。二重の冗長性を意図的に持たせています。

赤の規律

赤＝「1日の上限を超えた」1つだけ

赤の意味を1つに固定します。 勤務時間帯のルールを設けないため、赤くなるのは上限超過のときだけ。 通常時は完全なモノクロで、赤が出たこと自体が情報になります。

リスク（軽減済）

「上質に見える」問題は赤で軽減

白黒は何でも格好よく見えるため、超過が単なる装飾に見える危険がありました。 赤の導入でこの危険は大きく下がりました。 ただし赤は気づかせるだけで、行動そのものは変えません。

正直な懸念

この画面は依然として自分を止められない

モノクロ化は見た目の問題を解決するだけで、行動の問題は解決しません。 記録＋可視化のみの設計では、見なければ何も起きない。 ウィジェットと通知が要ります。

アイコン

モノクロ化でむしろ強化された

色に頼らなくなったぶん、周囲のカラフルなアイコンの中で 黒は輪郭として最も強く立つ。 黒地・白の円弧を推奨します。

実装

2テーマは変数だけで切替

この Light/Dark は CSS 変数の差し替えだけで成立しています。 実装でも同じトークン構造を使えば、 テーマ追加は変数セットの追加だけになります。

確認したいこと

Light / Dark はシステム追従で確定。 このページの切替は確認用のプレビューで、実機では OS の設定に自動で従います。

赤の使い方は確定（案B: 両方赤）。 赤＝「ルールが破られた」という単一の意味に固定し、 赤は上限超過のときだけ（リング・数字・7日間チャートの超過日）。
通常時は赤が1つも出ないため、赤が出たこと自体が情報になります。
