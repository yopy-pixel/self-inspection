# データの取り扱いと暗号化（データ主権ポリシー）

最終更新: 2026-09-14
**この文書は、以前の「データを端末外に一切送信しない」という制約を置き換える。**

---

## 0. 改訂の理由

当初は「データを端末外に一切送信しない」ことを制約としていた。

しかし集約サーバー（Cloudflare Workers + D1）を導入する方針となったため、
**この制約は成立しない。** 矛盾を残すと「送信してはいけない」と誤解されるため、
この文書で新しい制約を明示する。

**この文書が現在の制約である。**

---

## 1. 送信するもの（これだけ）

| 項目 | 例 | 用途 |
|---|---|---|
| パッケージ名 | `com.google.android.youtube` | アプリ別の集計 |
| アプリ表示名 | `YouTube` | 表示（後から解決できなくなる場合に備える） |
| 開始・終了時刻 | epoch millis | 使用時間の算出 |
| ローカル日付 | `2026-09-14` | 日次集計（端末が確定した日付） |
| 区間の閉じ方 | `PAUSED` など | 実測と推定の区別 |

**これ以外は送らない。**

## 2. 送らないもの（明示）

| 項目 | 理由 |
|---|---|
| **ウィンドウタイトル / 閲覧URL / 画面内容** | **そもそも記録しない設計。** PCエージェントでも既定OFF |
| 入力内容（キー入力・検索語・メッセージ） | 記録しない |
| スクリーンショット・画面録画 | 記録しない |
| 位置情報 | 取得しない |
| 連絡先・通話履歴・SMS | 取得しない |
| 端末識別子（Android ID / IMEI / 広告ID） | 取得しない。端末の識別は**サーバーが発行する UUID** のみ |
| ファイル・写真 | 取得しない |

> **「何を使ったか」は送るが、「何を見たか・何を入力したか」は送らない。**
> この線引きが本ポリシーの核心。

---

## 3. 暗号化（必須・省略しない）

### 3.1 転送時（in transit）

| 対策 | 実装 |
|---|---|
| **HTTPS（TLS）必須** | Worker が `http:` のリクエストを **403 で拒否**する |
| 証明書 | Cloudflare が `*.workers.dev` に正規証明書を自動付与 |
| 平文HTTPの禁止（端末側） | `android:usesCleartextTraffic="false"` ＋ network security config |
| HSTS | API専用のため不要（ブラウザで開かない） |

> **平文で送る経路を用意しない。** 端末側・サーバー側の**両方で**拒否する
> （片方だけだと設定ミスで素通りする）。

### 3.2 認証情報（最重要）

| 対象 | 対策 |
|---|---|
| 端末上のトークン | **EncryptedSharedPreferences**（Android Keystore 由来の鍵で暗号化） |
| サーバー上のトークン | **SHA-256 ハッシュのみ保存。平文は保存しない** |
| 平文トークンの扱い | 発行時に一度だけ返す。DB に残らない |
| トークンの粒度 | **端末ごとに別トークン**（共有パスワードにしない） |

**平文トークンを `SharedPreferences` に置いてはいけない。** root 化端末や
バックアップ経由で読まれる。

### 3.3 保存時（at rest）

| 対象 | 対策 |
|---|---|
| サーバー（D1） | Cloudflare の保存時暗号化 |
| 端末（Room） | OS のアプリサンドボックス内。`allowBackup="false"` でクラウドバックアップ対象外 |
| 端末上のトークン | 上記 3.2 |

---

## 4. 正直なリスク評価（過大な安心を与えない）

### 4.1 これは**エンドツーエンド暗号化ではない**

**Cloudflare はデータを復号できる。** TLS は Cloudflare で終端されるため、
Workers と D1 はデータを平文で扱う。

**なぜそうなるか:** サーバー側で集計（複数端末の合算・日次集計）を行う設計だから。
**集計するにはサーバーがデータを読む必要がある。** これはトレードオフであり、
回避するには「サーバーは暗号文だけを保存し、復号と集計は端末で行う」設計に
変える必要がある（サーバー側の集計を諦めることになる）。

**現時点の判断:** 集約の便益を優先し、TLS ＋ 認証情報保護で運用する。

### 4.2 端末を失った場合

`allowBackup="false"` のため**クラウドバックアップには残らない。**
一方で、暗号化されたトークンは端末と共に失われる（**復元不可**）。
サーバーにデータが残っていれば、再発行したトークンで復旧できる。

### 4.3 サーバーを止めれば端末内で完結する

**同期を無効にすれば、アプリは従来どおり端末内だけで動作する。**
アプリの表示は常にローカルの Room を読むため、**サーバー無しでも全機能が動く。**
これはこの設計の重要な性質である。

---

## 5. 実装上の遵守事項

実装者は以下を守ること。**破った場合はこのポリシーの違反となる。**

- [ ] 送信するフィールドは §1 のみ。追加する場合はこの文書を先に更新する
- [ ] `http://` を受け付けない（サーバー側で拒否）※実装済み
- [ ] `usesCleartextTraffic="false"` を設定する
- [ ] トークンは `EncryptedSharedPreferences` に保存する
- [ ] トークンを**ログに出さない**（`Log.d` に含めない）
- [ ] トークンを Intent の extra に平文で入れない
- [ ] 端末識別子（Android ID 等）を取得しない
- [ ] ウィンドウタイトルを記録しない（PCエージェントも既定OFF）
