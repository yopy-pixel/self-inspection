## 0. デザイン方針（確定）

| 項目 | 決定 |
|---|---|
| **色** | **白黒（彩度 0%）＋ 赤1色。赤＝「その日 上限を超えた」** |
| **テーマ** | **OS の設定に自動追従**（Light / Dark を両方用意。手動切替は設けない） |
| **言語** | アイコンは文字なし。UIは記号優先、必要なら英語 |
| **アイコン** | A. Ring（黒地に白の円弧） |
| **画面** | リング＋ランキング＋7日推移の**3要素**を1画面に |

### 検証済み（機械的に確認した事実）

| 検証 | 方法 | 結果 |
|---|---|---|
| 色相がゼロか | 全hex色の R=G=B を検査 | **純グレー20色＋赤2色**。他に有彩色なし |
| 赤の可読性 | WCAG コントラスト計算 | Light 5.16:1 / Dark 5.81:1（**AA 4.5 合格**） |
| レイアウト | 2テーマ×3状態で実測 | **6通りすべて余白28px・横はみ出し0**（§6参照） |
| リングの実色 | **ピクセルサンプリング** | 下記の表の通り、意図通りに描画 |
| UIの言語 | レンダリング文字列を抽出 | 画面・ウィジェットに**日本語ゼロ** |

**リングの実測色（ピクセル単位）:**

| テーマ | OK | CLOSE | OVER |
|---|---|---|---|
| Light | `#000000` (54%) | `#000000` (94%) | **`#C62828` 点線** |
| Dark | `#FFFFFF` (54%) | `#FFFFFF` (94%) | **`#FF453A` 点線** |

> **測定手法の注意:** `getComputedStyle().stroke` は SVG に対して**初期値を返すことがあり、
> 誤診を招く**。今回も一度これで「ダークでリングが黒い」と誤判定した。
> SVG の描画色を確認するときは**ピクセルを直接サンプリングする**こと。

## 1. 言語ポリシー

ユーザー要望:「**できれば言語なし。どうしても必要なところは英語で**」

| 原則 | 内容 |
|---|---|
| **1. 記号優先** | リング・バー・ドットで伝わる情報に単語を足さない |
| **2. 数字は言語ではない** | `3h 42m` / `18m` / `12:10` は単位記号が読めれば伝わる |
| **3. 文章は最小限・英語** | 避けられない文章は英語1行 |

### やってはいけないこと

- **アイコンに文字を入れない**
- **日本語をUIに置かない**（コメント・資料は日本語でよい）
- **文字列を安易に増やさない**（下記の語彙表が上限）

### アプリUIの語彙（全量）

| 用途 | 文字列 | 備考 |
|---|---|---|
| 今日の見出し | `Today` | 3箇所で共通 |
| 上限 | `limit 4h 00m` | 数字が主 |
| 残り（OK） | `1h 18m left` | |
| 残り（CLOSE） | `18m left` | |
| 超過（OVER） | `42m over` | 赤＋太字 |
| ランキング見出し | `Top apps` | ＋ `today` |
| 7日間見出し | `7 days` | ＋ `avg 3h 12m` |
| その他 | `Others` | 5位以降の合算 |
| 曜日 | `M T W T F S S` | 1文字。7列に収めるため |

**動詞は `left` / `over` の2語のみ。** 他言語追加は**置換だけ**で済む。

### 単位表記

- 画面内・ウィジェット大: `3h 42m`
- ミニウィジェット・ランキング: `3:42` / `1h12` / `48m`

## 2. パレット

### 基本 — 純グレー20色（彩度 0%）

**Light**

```
面    #FFFFFF    地    #F5F5F5    罫    #E4E4E4
主文字 #000000    副    #6E6E6E    三次   #A1A1A1
トラック #E9E9E9
```

**Dark**

```
地    #0A0A0A    面    #151515    罫    #252525
主文字 #FFFFFF    副    #9A9A9A    三次   #616161
トラック #242424
```

> **実装メモ:** Apple の実際のシステム色（`#F5F5F7` 等）は**わずかに青みを含む**。
> 「白黒」を厳密に満たすため、あえて**純グレーに寄せている**。実装時もこの値を使うこと。

### アクセント — 超過時のみ使う赤

| テーマ | 値 | コントラスト | 用途 |
|---|---|---|---|
| Light | `#C62828` | 5.16:1（地 #F5F5F5 上） | リング・`42m over` の文字 |
| Dark | `#FF453A` | 5.81:1（地 #0A0A0A 上） | 同上 |

### 赤を使う箇所（確定）

**赤は「その日 上限を超えた」の1つの意味だけに使う。**

| 赤くなる箇所 | 発火条件 |
|---|---|
| リングと `42m over` の文字 | 今日の合計が上限を超えた |
| 7日間チャートの超過した日 | その日 上限を超えた（履歴） |
| `today` のバー（OVER時） | 今日が上限を超えた |

**赤はこの3箇所のみ。** 通常時は赤が1つも出ないため、
**赤が出たこと自体が情報**になる。

> **確定した経緯:** 当初は「勤務時間帯の違反」も赤くする案（案B）で合意していたが、
> **勤務時間帯ルール自体を設けない**方針が確定したため（2026-09-14）、
> 赤は上限超過のみとなった。比較検討の記録は `red-usage.html`（現在は無効）を参照。

## 3. 状態の伝え方

### 形で3段階を区別する

| 状態 | 発火条件 | リングの形 | 色 |
|---|---|---|---|
| **OK** | 残り > 接近閾値 | 実使用率の円弧 | 黒（Dark: 白） |
| **CLOSE** | 残り ≤ 接近閾値（既定 **10分**） | 実使用率の円弧 | 黒（Dark: 白） |
| **OVER** | 実使用 > 上限 | **全周の点線** | **赤** |

**`stroke-dasharray` は状態ごとの固定値ではなく、実データから計算する:**

```
円周 = 2π × 88 ≈ 553
描画長 = 553 × min(実使用ミリ秒 / 上限ミリ秒, 1)
stroke-dasharray = "{描画長} {553 - 描画長}"
```

OVER のときだけ `6 11`（点線）に切り替える。

> **重要（実装時の注意）:**
> モックアップの 52% / 92% は「上限4時間・使用3時間42分」を仮定した**説明用の値**であり、
> **固定値ではない。** 実装では必ず実データから算出すること。
>
> **接近（CLOSE）はパーセントではなく残り時間で判定する（既定10分）。**
> 上限を4時間から1時間に変えれば、同じ「残り10分」でも塗り率は変わる。
> **塗り率を接近判定に使ってはいけない。**

### 三重の冗長性

**形・色・語**の3つで状態を伝える。どれか一つを見落としても分かる。

- 形: 途切れ → 閉じる → 壊れる（点線）
- 色: 黒 → 黒 → **赤**
- 語: `left` → `left` → `over`

### 超過時の扱い

- リングを点線化（`stroke-linecap: butt` に変更）
- トラックを赤の低不透明度（`.18`）にして全体を赤く読ませる
- `font-weight: 750` に上げる
- 文字色を赤に

## 4. アイコン

**採用: A. Ring** — 文字なし（text-free）

```
地        #000000
リング地   #3A3A3A
リング前景  #FFFFFF
半径 r=25（108×108 viewBox）／線幅 8.5
塗り率 70%（stroke-dasharray="110 47"）
```

- 白地版（A′）も用意。好みで選択可
- B（enso）は次点。人目に触れても意図が読まれにくい

### 実装メモ

- Android adaptive icon は**前景／背景の2層**
- 108×108dp のうち**中央72dpが安全領域**。四隅に要素を置かない
- モノクロ化で**アイコンはむしろ強化された**。
  周囲にカラフルなアイコンがあっても、黒は輪郭として最も強く立つ

### 「監視の目」を使わない理由

自分で自分を縛る道具に目のモチーフを置くと、監視されている感覚が強まり逆効果。

> 鏡（measure）であって警官（police）ではない。

## 5. テーマのシステム追従

**手動切替は設けない。OS の設定に自動追従する。**

### Android での実装

- `values/` と `values-night/` にリソースを分ける、または
- Compose なら `isSystemInDarkTheme()` を使う
- テーマ切替 UI は作らない（設定項目を増やさない方針）

### 理由

設定項目を増やすと、それ自体が「触る対象」になり、
アプリを開く理由が「設定いじり」にすり替わる。
このアプリの目的は設定ではなく**記録を見ること**なので、切替は持たない。

## 6. 起動時画面

上から3要素。**タブも階層も作らない。**

| # | 要素 | 役割 |
|---|---|---|
| 1 | リング＋今日の合計 | 一目で「今日どうだったか」 |
| 2 | アプリ別ランキング | **何に使ったか**（判断の材料） |
| 3 | 7日間推移 | 傾向 |

### 勤務時間帯ルールは設けない（確定 2026-09-14）

**アプリは違反を判定しない。** 「いつ何をどれだけ使ったか」を示し、
**それが問題かどうかは本人が判断する。**

| やらないこと | 理由 |
|---|---|
| 勤務時間帯の判定 | 依頼主の判断:「不要。見て自分で判断する」 |
| 違反の自動検出・赤表示 | アプリが善悪を決めると、判断を委ねてしまう |
| NGアプリの事前登録 | 登録の手間が発生する |

そのため**違反セクションは存在しない。**
ランキングとチャートが判断材料を提供し、評価は本人が行う。

> **実装への影響（重要）:** `rules/RuleEngine.kt` に `WORKTIME_USAGE` として
> 実装済みのロジックは**不要になる**。詳細は §9 を参照。

### 過剰な赤を避ける設計だった経緯

違反を表示していた時期は、セッション単位で1日に何件も発生するため
アプリ別集約（`YouTube · 54m · 3×`）で行数を一定に保つ必要があった。
**違反セクションの削除により、この問題自体が消滅した。**

### レイアウト制約（実測済み）

- 画面高 716px、表示領域 680px
- 内容高 **652px**、余白 **28px**（6通りすべてで同一）
- リング直径 **196px**（違反セクション削除で空いた分を充当）
- ランキング **6行**（YouTube / X / Chrome / LINE / Instagram / Others）
- 要素を足すと溢れるため、**追加時は必ず再測定すること**

## 7. ウィジェット（Phase 6 で実施・確定）

**これが最も重要。** アプリを開かずに今日の状況が見える。

理由: 自分を「自堕落」と表現する人が**自分から監視アプリを開くことは期待できない**。
見なければ何も起きない設計は機能しない。

| 種別 | 内容 |
|---|---|
| 標準 | `Today` / `3h 42m` / バー / `limit 4h`・`18m left` |
| ミニ | `Today` / `3:42` / バー |

**役割分担:**
- ウィジェット = **その場で気づく用**（見なくても目に入る）
- ダッシュボード = **夜に振り返る用**（自分から開く）

モノクロでもバーの長さが状態を伝えるため、色は不要。

## 8. 実装上の注意

- グラフは **`Canvas` で自作**する。外部チャートライブラリは不要
- 文字列は `strings.xml` に英語で定義し**ハードコードしない**
- Light/Dark は**同一のトークン構造**で実装する
- リングの `stroke-dasharray` を状態で切り替える。**形が状態を担う**ため、
  ここを色だけに戻すと設計意図が壊れる
- **SVG の色を検証するときはピクセルを見る**（`getComputedStyle` は誤る）

## 9. リスクと未確定事項

### リスク

**超過が「上質」に見える問題は赤である程度軽減された。**
ただし赤は**気づかせる**だけで、行動そのものは変えない。
根本的な限界（アプリを開かなければ何も起きない）は残る。

**赤の日常化リスクはほぼ解消された。**
赤は「上限超過」の1状態のみに使うため、1日に何度も赤が出ることはない
（超過は1日1回、しかも夜まで続く状態）。

**新たな限界:** 勤務時間帯ルールを削除したため、
**アプリは「使いすぎ」しか教えない。** 「いつ使ったか」は示すが、
それが問題かどうかは本人が判断する必要がある。
判断材料（アプリ別・時間帯別）が十分に読み取れるUIであることが重要。
